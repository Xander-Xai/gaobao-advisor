# 中国 AI 法规合规清单模板

> 适用于：在中国境内面向公众提供生成式 AI 服务的所有应用。基于截至 2026 年 6 月的最新法规整理。

---


## 逐项合规检查清单

### A. 算法备案（必做）

```yaml
algorithm_filing:
  法律依据: '《生成式AI服务管理暂行办法》第9条 + 《算法推荐管理规定》第24条'
  负责机关: '国家互联网信息办公室（CAC）'
  备案平台: 'http://beian.cac.gov.cn'

  需要提交的材料:
    - '算法基本信息（名称、类型、应用场景）'
    - '算法原理说明（技术架构、训练数据来源）'
    - '安全评估报告（自评或第三方）'
    - '服务协议和隐私政策'
    - '投诉举报处理机制说明'

  备案时限: '提供服务之日起 30 个工作日内'
  更新义务: '算法重大变更后 10 个工作日内更新备案'

  本项目具体操作:
    - '填报算法类型：对话生成类'
    - '填报应用场景：高考志愿咨询'
    - '填报训练数据：公开院校/专业/分数线数据 + 公开政策文件'
```

### B. 安全评估（必做）

```yaml
security_assessment:
  法律依据: '《暂行办法》第7条、第17条'
  评估内容:
    training_data:
      - '训练数据来源合法性（必须有合法授权或为公开数据）'
      - '训练数据质量（无歧视、无虚假、无违法内容）'
      - '训练数据标注合规性（标注人员管理、标注流程规范）'
    output_safety:
      - '输出内容是否符合社会主义核心价值观'
      - '是否可能生成违法不良信息'
      - '幻觉/虚假信息风险评估'
    data_protection:
      - '用户数据收集/使用/存储是否符合 PIPL'
      - '跨境数据传输评估（如果使用境外 LLM API）'
    algorithmic_fairness:
      - '是否因地域/性别/民族产生歧视性推荐'
      - '推荐结果的公平性审计'

  频率: '首次上线前 + 每年至少一次 + 重大变更时'
```

### C. 内容标识（必做）

```yaml
content_labeling:
  法律依据: '《暂行办法》第12条 + 《深度合成管理规定》第6条'
  要求: 'AI 生成的内容必须明确标识'

  实现方式:
    方式一_响应内标识: |
      每条 AI 生成的推荐/分析响应末尾附加：
      「本回答由 AI 生成，基于公开数据，仅供参考。」
    方式二_界面标识: |
      在对话界面固定位置展示标识，
      如页面顶部："AI 志愿助手 · 回答基于公开数据 · 仅供参考"
    方式三_双重标识: |
      界面固定标识 + 涉及具体推荐时的响应内标识（推荐）

  不可省略场景:
    - '涉及具体院校推荐'
    - '涉及录取概率分析'
    - '涉及专业就业前景'
    - '涉及任何可能影响用户决策的内容'
```

### D. 内容红线（硬性禁止）

```yaml
prohibited_content:
  法律依据: '《暂行办法》第4条'

  必须硬拦截的内容:
    危害国家安全:
      - '煽动颠覆国家政权'
      - '推翻社会主义制度'
      - '分裂国家'
      - '破坏国家统一'
    违反法律法规:
      - '宣扬恐怖主义、极端主义'
      - '宣扬民族仇恨、民族歧视'
      - '暴力、淫秽色情信息'
      - '虚假信息、扰乱经济和社会秩序'
    违反社会主义核心价值观:
      - '歪曲、丑化、亵渎、否定英雄烈士事迹和精神'
      - '散布谣言、扰乱社会秩序'

  高考场景特有的红线:
    - '推荐学生作弊方法'
    - '提供泄露的考试内容'
    - '散布虚假的招生政策'
    - '挑拨学生与学校/教育部门的对立情绪'
    - '基于地域/民族/性别进行歧视性推荐'
```

### E. 用户权益保障

```yaml
user_rights:
  投诉举报机制:
    法律依据: '《暂行办法》第15条'
    要求:
      - '提供便捷的投诉举报入口（界面内可访问）'
      - '公示投诉举报处理流程和时限'
      - '收到投诉后 7 个工作日内处理并反馈'
      - '投诉记录保留不少于 3 年'
    实现:
      - '对话界面右上角 "反馈/举报" 按钮'
      - '支持选择反馈类型（内容不准确/有害内容/其他）'
      - '后台工单系统自动流转'

  用户知情权:
    - '告知用户正在与 AI 对话（非真人）'
    - '告知 AI 回答的局限性'
    - '提供"为什么推荐这个学校"的可解释性'
```

### F. 数据跨境评估

```yaml
cross_border_data:
  触发条件: '使用境外 LLM API（如 OpenAI、Anthropic、Google）'
  法律依据: '《数据安全法》第31条 + PIPL 第38-43条'

  方案一_数据不出境:
    description: '使用国内 LLM（DeepSeek、Qwen、GLM、文心等）'
    compliance: '无需跨境评估，推荐方案'

  方案二_出境但合规:
    description: '必须使用境外 API 时'
    requirements:
      - '完成数据出境安全评估（向 CAC 申报）'
      - '与境外接收方签订标准合同'
      - '确保境外接收方不保留中国用户数据'
      - '对传输数据进行脱敏处理'

  建议: '高考成绩等敏感数据应优先使用国内模型处理'
```

## 合规执行时间线

```
发布前（T-30天）
├── T-30: 启动算法备案材料准备
├── T-21: 完成安全评估报告
├── T-14: 提交算法备案申请
├── T-7:  完成内容标识部署
├── T-7:  完成投诉举报通道开发
├── T-3:  完成隐私政策上线 + 用户同意流程
└── T-0:  上线

上线后（T+30天内）
├── T+7:  首周合规监测（内容安全事件=0为目标）
├── T+14: 投诉处理机制验证
├── T+30: 首月合规总结报告

持续运营
├── 每季度: 安全评估更新
├── 每年: 算法备案更新
├── 重大变更后: 10个工作日内更新备案
└── 安全事件: 24小时内上报
```

## 与现有 prompts 的集成

你项目中 v2.1 的免责升级已经覆盖了 C（内容标识）和部分 D（内容红线）的基础。建议补全：

1. **A 算法备案**：需要单独准备材料，不是 prompt 能解决的
2. **B 安全评估**：基于现有的 `final-acceptance` 报告扩展
3. **C 内容标识**：v2.1 已有基础，建议加强为双重标识
4. **D 内容红线**：v2.2 的禁词表需要扩展（增加高考特有红线）
5. **E 用户权益**：当前完全没有投诉举报机制的设计
6. **F 跨境评估**：取决于你使用的 LLM 供应商
