# Sensitive data handling

> 历史安全事件说明：本文提及的数据库、备份和外部副本属于非公开取证范围，
> 不代表当前仓库数据。当前仓库仅分发合成数据。Historical / non-public
> security-incident documentation; not a current data inventory.

This repository ships only the deterministic synthetic dataset generated by
`scripts/seed_demo_data.py`. Databases, SQL dumps, backup archives and real
environment files must never be committed.

## Local rule

```bash
# Generate the demo database locally (gitignored)
python -m scripts.seed_demo_data --db data/demo.db --reset

# Optional: install the local pre-commit guard
pip install pre-commit
pre-commit install
```

The guard blocks tracked/staged `*.db`, `*.sqlite`, `*.sql`, `*.sql.gz`,
`*.dump`, `*.bak`, `*.log`, real `.env*` files, backup directories and files
larger than 10 MiB. CI runs the same guard against every tracked file before
the full-history gitleaks scan.

## Incident rule

If a database, dump or credential is committed:

1. Do not only delete it in a new commit; the object remains in history.
2. Revoke/rotate any live credential immediately.
3. Preserve an access-controlled, offline copy for forensics.
4. Rewrite history only in an isolated sandbox, with owner authorisation.
5. Ask GitHub Support to purge PR refs, caches and unreachable objects.
6. Treat third-party forks/clones as out of our control and document the
   residual risk.

Issue #58 tracks the current historical-exposure case. The public report is
`docs/audits/gaobao-issue-58-remediation.md`.
