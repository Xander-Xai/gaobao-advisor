## 3. Data provenance

- The default dataset is deterministic synthetic data generated by
  `scripts/seed_demo_data.py`; schools carry `（合成）` and
  `special_type=SYNTHETIC_DEMO_DATA`.
- The seed writes a `dataset_snapshots` row with version, profile, generation
  time and covered years. The public overview reads it; a missing row is shown
  as unregistered instead of inferred.
- The public data page reports counts, year range, per-year coverage, schools
  with scores/plans and profile labels from database queries.
- Trends are grouped by `subject_type`; different provinces/exam modes/subject
  types are not merged into one line.
- No real admissions database, user messages, credentials or private plans
  were added. The historical Git object tracked by Issue #58 is not
  redistributed or relabelled as synthetic.

## 7. Residual risks

1. Issue #58: historical object and provenance/authorization remain unresolved;
   owner accepted the residual risk for this cycle. Do not describe it as
   purged or licensed.
2. Anonymous sessions are HMAC capability tokens without expiry/revocation.
3. The demo has no production SLA, real admissions accuracy claim or
   production-scale RAG evaluation.
4. MySQL/Redis/worker were validated on throw-away local containers; this is
   not a production capacity approval.
5. The public catalog currently targets the demo/custom admissions schema; a
   future multi-source ingestion layer must record per-source provenance rather
   than treating every row as equivalent.
