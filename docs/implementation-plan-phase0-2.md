### Task 0.2: 结构化引导卡片（省份→分数→选科）

**描述**：将当前的纯文本欢迎消息 + 6 个硬编码快速提问按钮，替换为分步结构化引导卡片。用户通过点击选择省份、输入分数、选择选科，系统自动组装为首条消息发送给 AI，无需自己组织语言。

**实现方案**：
1. 在首次加载时（无 user messages 时），渲染 3 列引导区域：
   - **Step 1**: 省份选择 — `st.selectbox` 带 31 个省份选项
   - **Step 2**: 分数输入 — `st.number_input` 范围 0-750，带校验
   - **Step 3**: 选科选择 — 根据已选省份动态判断是 3+3 / 3+1+2 / 传统文理，渲染对应的选科标签云（用 `st.multiselect` 或 button group）
2. 选择完成后，自动组装为 `"我是{province}考生，考了{score}分，选科是{subjects}，帮我分析能上什么学校"` 并触发发送
3. 保留一个"跳过引导，直接提问"按钮给不想走流程的用户
4. 引导完成后，后续交互恢复正常聊天模式

**验收标准**：
- [ ] 新用户打开页面 → 看到 3 步引导卡片，而不是 6 个快速提问按钮
- [ ] 选择省份+分数+选科后 → 自动组装消息并发送 → AI 正常回复
- [ ] 点击"跳过引导" → 显示原始的 `st.chat_input`，可自由输入
- [ ] 老用户（已有消息历史）不显示引导卡片
- [ ] 所有现有测试通过

**验证**：
- [ ] `python3 -m pytest tests/ -q` 全部通过
- [ ] 手动检查：完整走一遍引导流程 → 对话正常开始

**依赖**：无

**涉及文件**：
- `app.py` L75-82（QUICK_QUESTIONS 常量）
- `app.py` L1349-1400（欢迎消息 + 快速提问渲染 + pending question 编辑流程）
- `app.py` CSS 部分（新增引导卡片样式）
- `agent.py` L237-245（PROVINCES 常量引用）

### Task 0.3: 多阶段加载指示器

**描述**：将当前的单阶段加载提示（`🔍 正在分析你的信息...`）替换为随时间递进的多阶段提示，减少用户等待焦虑。

**实现方案**：
在 `loading_placeholder` 处使用 `threading.Timer` 或 Streamlit 的自动刷新机制，在不同时间点更新加载提示：
- 0-1 秒：`🔍 正在匹配你的信息...`
- 1-3 秒：`📊 正在查询院校数据...`
- 3-6 秒：`🧠 AI 顾问正在分析，马上就好...`
- 6 秒+：`⏳ 正在生成个性化建议，复杂情况可能需要更多时间...`

由于 Streamlit 的单线程限制，使用 `st.empty()` + `time.sleep` 在独立线程中更新不可行。**替代方案**：使用 CSS 动画实现文字渐变切换效果，或在第一个 data_hints 返回前/后分别更新一次提示文本（在代码中已有 `loading_placeholder.empty()` 的时机处插入中间状态）。

**验收标准**：
- [ ] 等待 AI 回复时，用户看到的提示信息会随时间变化
- [ ] 第一个流式 chunk 到达后，加载提示消失（与现有行为一致）
- [ ] 加载提示的 CSS 动画保持流畅

**验证**：
- [ ] `python3 -m pytest tests/ -q` 全部通过
- [ ] 手动检查：发送问题后观察提示变化

**依赖**：无

**涉及文件**：
- `app.py` L1516-1556（加载/spinner 逻辑）
- `app.py` L607-620（loading-step CSS）

**预估规模**：S（1 file）

### Task 1.2: 数据年份强化 + 免责声明自动注入

**描述**：确保 AI 回复中的每条分数线数据都明确标注年份，并在涉及推荐类回复时自动追加免责声明，提升数据可信度和法律合规性。

**当前状态**：
- `format_admission_info()` 已包含 `{year}年` 标签（gaokao_data.py L773）✅
- `system_prompt.md` 已有免责声明参考文本（L599-606）✅
- 但免责声明仅作为参考，AI 不一定会在每次回复中加入

**实现方案**：
1. **强化年份指令**：在 `agent.py` 的 `_build_system_message()` 的数据查询规则（L883-894）中，追加明确指令："回复中每条录取数据必须标注数据年份，格式为 `[2025年数据]`；如果数据来自不同年份，分别标注。"
2. **自动追加免责声明**：在 `chat()` 和 `chat_stream()` 的回复末尾（现有 disclaimer 逻辑 L1560-1564 处），扩大触发条件 — 不仅是"报告类关键词"，而是所有包含分数线推荐的回复都追加简短免责声明。
3. **移除面向用户的 T1/T2/T3/T4 标签**：在 `format_admission_info()` 输出中，将内部的 T1/T2 来源标签替换为用户可理解的描述（如"教育部官方数据"、"百度高考数据"）。这仅影响注入给 AI 的数据提示，不影响 AI 的内部推理。

**验收标准**：
- [ ] AI 回复中每条分数线数据都有年份标注
- [ ] 涉及学校推荐的回复末尾自动追加免责声明
- [ ] 数据来源标签对用户友好（不再是 T1/T2/T3/T4）
- [ ] 所有现有测试通过

**验证**：
- [ ] `python3 -m pytest tests/ -q` 全部通过
- [ ] 手动检查：问一个具体学校 → 确认年份标注 + 免责声明

**依赖**：无

**涉及文件**：
- `agent.py` L883-894（数据查询规则）+ L1560-1564（免责声明追加）
- `gaokao_data.py` L755-780（`format_admission_info()` 来源标签美化）
- `tests/test_p1_features.py`（新增测试）

**预估规模**：M（2-3 files）

### Task 1.3: 推荐学校时自动过滤选科不符专业

**描述**：当用户已提供选科信息，在 AI 推荐学校/专业时，自动通过 `check_user_subject_compatibility()` 过滤掉不满足选科要求的专业，并在注入数据中明确标注匹配/不匹配。

**当前状态**：
- `_inject_subject_compatibility()` 已实现（agent.py L908-923），在用户有选科时注入全局兼容性概览
- 但这个注入是在咨询意图时一次性注入，**没有针对具体推荐学校/专业做定向过滤**

**实现方案**：
1. 在 `_query_data_hints()` 的录取数据查询（L959-992）之后，如果用户已填写选科，对查询到的专业调用 `check_user_subject_compatibility()` 并将匹配结果附加到 data_hints 中
2. 在 `format_admission_info()` 结果中追加一行：`选科匹配：✅ 物理+化学 符合要求` 或 `⚠️ 该专业要求必选政治，你的选科不符合`
3. 在 `_query_rank_recommendations()` 的冲/稳/保推荐结果中，对每个推荐学校的专业调用选科检查，过滤掉不匹配的专业

**验收标准**：
- [ ] 用户提供选科（如"物化生"）后，AI 推荐的学校/专业都标注了选科匹配状态
- [ ] 选科不符的专业在推荐中被标记 ⚠️ 并说明原因
- [ ] 当用户未提供选科时，行为不变（不注入选科信息）
- [ ] 所有现有测试通过

**验证**：
- [ ] `python3 -m pytest tests/ -q` 全部通过
- [ ] 手动检查：设定选科为"物化生" → 查询临床医学 → 应显示"符合"；查询法学 → 应显示"要求政治"

**依赖**：无（`check_user_subject_compatibility()` 已存在）

**涉及文件**：
- `agent.py` L959-992（录取数据查询后追加选科检查）
- `agent.py` L1196-1203（推荐结果后追加选科过滤）
- `tests/test_p2_features.py`（新增测试）

**预估规模**：M（2-3 files）

### Task 2.4: 动态上下文感知快捷提问

**描述**：将当前的 6 个硬编码快速提问按钮，替换为根据已收集的 slot 信息动态生成的上下文感知提问建议。

**当前状态**：
- 6 个场景化快速提问已实现（app.py L75-82）
- agent.py 的 slot 系统（7 个槽位）运行良好

**实现方案**：
1. 根据 `st.session_state` 中 advisor 的 slots 状态，动态生成快捷提问：
   - **无任何 slot 填充时**：显示引导型提问（与 Task 0.2 的引导卡片互补）：
     - "帮我分析一下我的选择"
     - "今年形势怎么样？"
   - **省份+分数已知，选科未知时**：
     - "我选了{subjects}，帮我看看有什么选择"
     - "不限选科能报什么？"
   - **省份+分数+选科已知时**：
     - "帮我看看冲稳保各有哪些学校"
     - "我想去{region}的学校"
     - "什么专业好就业？"
   - **推荐结果已展示后**（有 AI 回复中提到具体学校时）：
     - "XX大学详情"（从最近的 AI 回复中提取学校名）
     - "这几所学校怎么排序？"
     - "帮我生成志愿表"
2. 快捷提问按钮数量控制在 3-4 个，避免选择过载

**验收标准**：
- [ ] 快捷提问内容随对话进展动态变化
- [ ] 已知省份时，提问中包含省份名
- [ ] AI 推荐学校后，快捷提问包含学校相关追问
- [ ] 所有现有测试通过

**验证**：
- [ ] `python3 -m pytest tests/ -q` 全部通过
- [ ] 手动检查：输入省份+分数 → 快捷提问变化；AI 回复后 → 出现追问按钮

**依赖**：无（slot 系统和 AI 回复解析逻辑已存在）

**涉及文件**：
- `app.py` L75-82（QUICK_QUESTIONS）+ L1361-1369（快捷提问渲染）

## Risks and Mitigations

| 风险 | 影响 | 缓解方案 |
|------|------|----------|
| Streamlit `st.rerun()` 全页刷新导致引导卡片闪烁 | 中 | 将引导状态存入 `session_state`，避免重复渲染 |
| 多阶段加载在 Streamlit 单线程下难以实现时间触发 | 中 | 改用 CSS 关键帧动画实现文字渐变，或仅做 2 阶段（第一个 chunk 前后） |
| LLM 不一定遵守年份标注指令 | 低 | 强化 system_prompt 指令 + 在 post-processing 中用正则检测补标 |
| 选科过滤增加每次查询的 DB 调用次数 | 低 | 仅对 top-15 推荐结果做检查，已有 `check_user_subject_compatibility` 是单次 DB 查询 |
| 动态快捷提问需要在 Streamlit 刷新循环中解析 AI 回复 | 中 | 在 `st.session_state` 缓存解析结果，仅在新 AI 回复时重新解析 |

## Open Questions

1. **Task 0.2 引导卡片样式**：是用 Streamlit 原生组件（selectbox + number_input）还是用 `st.markdown(unsafe_allow_html=True)` 渲染自定义 HTML 卡片？建议优先用原生组件（兼容性好、可交互），仅在需要视觉升级时用 HTML。
2. **Task 1.2 T1/T2 标签替换范围**：是只替换用户可见的 `format_admission_info()` 输出，还是连 agent 内部推理链中的标签也替换？建议仅替换 `format_admission_info()` 输出，内部保留 T1/T2 供 AI 判断数据可信度。
3. **Task 1.3 选科过滤的严格程度**：是完全隐藏不匹配的专业（硬过滤），还是标记 ⚠️ 但仍然展示（软过滤）？建议软过滤（标记但展示），因为部分学校有"相近专业可调剂"的情况。
