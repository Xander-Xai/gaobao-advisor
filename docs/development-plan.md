# 开发计划：xuefeng-advisor 用户体验升级

> 制定日期：2026-06-12
> 基于：[用户视角体验审计报告](user-experience-audit.md)
> 目标：让家长/学生打开就能用、用了就信任、信任就能落地

---

## 总体策略

```
Phase 0 (零门槛)  →  Phase 1 (数据可信)  →  Phase 2 (结果好用)  →  Phase 3 (产品闭环)
   去掉技术障碍          让数据说话             可视化+工具           持久化+分享
   ──── 1周 ────       ──── 2周 ────         ──── 2周 ────       ──── 2周 ────
```

---

## Phase 0：零门槛体验（1 周）

> 目标：家长打开链接，3 秒内能开始对话，不需要任何技术知识

### Task 0.1：后端预配置 API Key，移除用户侧输入

- **文件**：[app.py](app.py) L232-291
- **改动**：
  - 部署时必须在 `.env` 或 `st.secrets` 中配好 `LLM_API_KEY`
  - 移除侧边栏的 API Key 输入框和"使用此 Key"按钮
  - 如果后端没有配置 key，显示友好的维护页面而不是输入框
- **验收**：用户打开页面 → 直接看到欢迎消息和输入框 → 零配置开始聊天

### Task 0.2：首次使用引导流程

- **文件**：[app.py](app.py) L37-55（欢迎消息和快速提问）
- **改动**：
  - 重写欢迎消息：简短问候 + 3 步引导（选省份→填分数→说想法）
  - 替换 6 个硬编码快速问题为**动态引导卡片**：
    - 第一步：选择省份（下拉框或热门省份按钮组）
    - 第二步：输入分数（带校验的数字输入）
    - 第三步：选择兴趣方向（标签云选择）
  - 引导完成后自动组装成首条消息发送给 AI
- **验收**：新用户 3 步点击即可完成首次咨询，不需要自己组织语言

### Task 0.3：加载体验优化

- **文件**：[app.py](app.py) L409
- **改动**：
  - 将 `st.spinner("正在分析中，请稍候...")` 替换为分阶段提示：
    - 第 1 秒：「正在匹配你的信息...」
    - 第 3 秒：「正在查询院校数据...」
    - 第 6 秒：「AI 顾问正在分析，马上就好...」
  - 添加"思考中"动画（可用 CSS 骨架屏或打字机效果）
- **验收**：等待期间用户不焦虑，知道系统在工作

## Phase 1：数据可信（2 周）

> 目标：用户查询任何省份 200 分以上的院校，都有数据可查

### Task 1.1：扩大数据导入范围

- **文件**：[scripts/import_baidu_gaokao.py](scripts/import_baidu_gaokao.py)
- **改动**：
  - 扩展导入参数：覆盖全部 30 个主要省份 × 近 3 年（2023/2024/2025）
  - 扩大学校范围：不只是 top 80，改为全量导入（百度高考 API 支持分页）
  - 新增批次覆盖：本科一批 + 本科二批 + 专科批
  - 新增专业级分数线导入（百度高考 API 的 `majorscore` 接口）
- **验收**：
  - 数据库中至少 20 个省份 × 3 年 × 2 批次有数据
  - 至少 500+ 所院校有录取分数线
  - 查询"河南 480 分"能返回真实推荐结果

### Task 1.2：数据时效性和来源标注

- **文件**：[agent.py](agent.py) L443-556（数据注入逻辑）+ [system_prompt.md](system_prompt.md)
- **改动**：
  - 每条注入数据附加年份标签：`[2025年数据]` 而不是 `[T1]`
  - 在 AI 回复中强制要求注明数据年份
  - 添加免责声明文案到 system_prompt：「以上数据仅供参考，请以各校官方招生简章为准」
  - 移除面向用户的 T1/T2/T3/T4 数据等级标注
- **验收**：AI 回复中每条分数线都带年份，结尾有免责声明

### Task 1.3：选科约束查询

- **文件**：[gaokao_data.py](gaokao_data.py) + [agent.py](agent.py) L443-556
- **改动**：
  - 新增 `query_subject_requirements(school_id, province, year)` 函数，查询 `EnrollmentPlan.subject_requirement`
  - 在推荐学校时，如果用户已提供选科信息，自动过滤掉不满足选科要求的专业
  - 在 AI 回复中提醒用户：「你选的物化生，这个学校的临床医学要求物化，符合」或「该专业要求必选政治，你的选科组合不符合」
- **验收**：推荐结果自动排除选科不符的专业，并在回复中明确标注

### Task 1.4：院校信息补全

- **文件**：[scripts/seed_data.py](scripts/seed_data.py) + 新增 `scripts/import_schools_full.py`
- **改动**：
  - 补充普通本科和专科院校的基础信息（名称、省份、城市、类型、层次）
  - 补充院校官网 URL、招生办电话（公开信息）
  - 确保 `crud.get_school_by_name()` 的模糊匹配覆盖常见别名（如"北大"→"北京大学"）
- **验收**：用户输入任何正规院校名称都能匹配到

## Phase 2：结果好用（2 周）

> 目标：推荐结果不再是"一坨文字"，而是可浏览、可比较、可操作的结构化信息

### Task 2.1：冲/稳/保结构化卡片

- **文件**：[app.py](app.py)（新增渲染逻辑）+ [agent.py](agent.py)（结构化输出）
- **改动**：
  - AI 回复中的学校推荐改为**结构化数据块**（JSON 或标记格式），前端解析后渲染为卡片
  - 每张卡片包含：学校名、城市、层次标签（985/211/双一流）、往年最低分、往年最低位次、录取概率评估
  - 冲/稳/保三组用不同颜色区分（红/蓝/绿）
  - 卡片可点击展开查看详情（专业列表、就业数据）
- **实现方案**：
  - agent.py 输出中用 `<!--SCHOOL_DATA:{json}-->` 标记包裹结构化数据
  - app.py 解析标记，用 `st.columns()` + 自定义 CSS 渲染卡片
- **验收**：推荐 15 所学校时，按冲/稳/保三组分列，每校一张信息卡片

### Task 2.2：院校详情面板

- **文件**：[app.py](app.py)（新增组件）
- **改动**：
  - 卡片可展开查看：
    - 学校基本信息（层次、类型、排名）
    - 近 3 年在该省的录取分数线趋势
    - 王牌专业（学科排名 A 级以上）
    - 就业数据（平均薪资、就业率）
  - 使用 Streamlit 的 `st.expander()` 实现折叠
- **验收**：点击任意推荐学校，展开看到 4 类详细信息

### Task 2.3：志愿表生成工具

- **文件**：新增 [app.py](app.py) 中的侧边栏工具 or 新页面
- **改动**：
  - 在侧边栏添加"生成志愿表"按钮
  - 基于当前推荐结果，自动生成志愿排序建议：
    - 2 冲 + 5 稳 + 3 保 的比例建议
    - 每个志愿标注风险等级
    - 按往年分数从高到低排序
  - 支持导出为文本摘要（可复制粘贴）
- **验收**：用户聊完后，一键生成可参考的志愿表草案

### Task 2.4：快捷操作优化

- **文件**：[app.py](app.py) L48-55
- **改动**：
  - 快速提问改为**场景分类**而非具体案例：
    - 「我是高分考生，想冲名校」
    - 「我分数中等，想选好就业的专业」
    - 「我分数偏低，想找个靠谱出路」
    - 「我家有行业资源，想利用起来」
    - 「我在纠结选科，想听建议」
  - 对话中推荐的学校名称可作为快捷追问按钮：「这所学校详情」「还有类似的吗」「对比 XX 大学」
- **验收**：用户不需要自己组织问题，点点就能深入探索

## Phase 3：产品闭环（2 周）

> 目标：对话不丢失，结果可分享，形成从查询到决策的完整链路

### Task 3.1：对话持久化

- **文件**：[agent.py](agent.py) + [app.py](app.py) + [db/models.py](db/models.py)
- **改动**：
  - 新增 `Conversation` 表：session_id, user_label, messages_json, slots_json, created_at, updated_at
  - 用户首次访问时生成 session_id（存 cookie 或 URL 参数）
  - 每轮对话后自动保存到数据库
  - 重新打开页面时自动恢复对话（通过 session_id）
  - 侧边栏显示"历史对话"列表
- **验收**：关闭浏览器后重新打开，对话完整恢复

### Task 3.2：结果导出与分享

- **文件**：[app.py](app.py)
- **改动**：
  - 添加"导出咨询报告"按钮：
    - 汇总用户的省份/分数/选科信息
    - 列出所有推荐学校（冲/稳/保分组）
    - 包含关键数据和 AI 建议
    - 格式化为 Markdown 或可打印的 HTML
  - 添加"分享给家人"按钮：生成带 session_id 的链接
- **验收**：用户可以把咨询结果发给爸妈看

### Task 3.3：对话记忆增强

- **文件**：[agent.py](agent.py) L415
- **改动**：
  - 扩大上下文窗口：从 10 轮提升到 20 轮（40 条消息）
  - 超出窗口后，自动摘要之前的关键信息作为 system 消息注入
  - 摘要内容包括：已讨论的学校、用户的偏好变化、已排除的方向
- **验收**：聊 20 轮后 AI 仍然记得用户最初的需求和之前的讨论要点

### Task 3.4：移动端适配增强

- **文件**：[app.py](app.py) CSS 部分
- **改动**：
  - 增强移动端 CSS：
    - 侧边栏默认折叠
    - 快速提问按钮改为单列全宽
    - 字体和间距针对手机优化
    - 卡片组件在窄屏下变为全宽堆叠
  - 测试微信内置浏览器兼容性
- **验收**：在手机微信中打开，核心功能可用，阅读无困难

## 验收标准汇总

| Phase | 关键验收指标 |
|-------|-------------|
| Phase 0 | 新用户从打开到首次对话 < 30 秒，不需要任何技术知识 |
| Phase 1 | 查询任意省份 200 分以上，至少返回 5 所真实院校推荐 |
| Phase 2 | 推荐结果按冲/稳/保分组展示，可展开查看详情，可一键生成志愿表 |
| Phase 3 | 关闭页面后重新打开对话不丢失，可导出咨询报告 |

## 技术风险提示

| 风险 | 影响 | 缓解方案 |
|------|------|----------|
| 百度高考 API 变更 | 数据导入失败 | 保持 Zhiyuan API 作为备用数据源 |
| Streamlit 框架限制 | 卡片交互受限 | 用 `st.markdown(unsafe_allow_html=True)` 渲染自定义 HTML 组件 |
| LLM 结构化输出不稳定 | 卡片解析失败 | 在 agent 层做正则兜底，解析失败回退到纯文本展示 |
| 数据库膨胀 | 查询变慢 | 为 AdmissionScore 添加复合索引，限制历史数据保留年限 |
| 微信浏览器兼容 | 样式错乱 | 避免使用现代 CSS 特性，用 Flexbox 替代 Grid |
