## 课程一：RAG 实战——从 0 到 1 做一个 AI 顾问（¥99，10 节课）

### 课程概述

本课程以 gaobao-advisor 项目（一个日均服务数百用户的高考志愿 AI 顾问）为案例，手把手带你从零构建一个完整的 RAG 应用。你将学到：如何设计知识库并将其拆分为可检索的语义块、如何用混合检索（向量 + 关键词）替代昂贵的纯向量方案、如何用多层数据管线（本地数据库 → 第三方 API → 搜索引擎降级）实现 99% 的数据可用率、如何通过提示词工程让 LLM 输出专业且有个性的回答、以及如何用质量控制模块（情绪检测、交叉验证、反模式检查）防止 AI 幻觉。课程结束时，你将拥有一个可部署到 CLI / Web / API / Docker 四种端口的完整 AI 顾问应用。

### 目标学员

- 有 Python 基础（能写函数、装包、用命令行）的开发者
- 想用 AI 做知识付费、垂直领域顾问、企业内部助手的独立开发者/创业者
- 听过 RAG 概念但没实际做过的工程师
- 正在做或计划做 AI 应用的产品经理、技术负责人

### 学完你能做到

1. 独立设计并实现一套完整的 RAG 知识检索系统（含分块、嵌入、混合检索）
2. 搭建多源数据管线，实现结构化数据（数据库）+ 非结构化数据（文档）的统一查询
3. 编写 500 行以上的专业级系统提示词，包含多语调、多场景、自检机制
4. 实现情绪检测、交叉验证、反模式检查等质量控制模块
5. 将 AI 顾问部署到 CLI、Streamlit Web、FastAPI REST API、Docker 四种形态
6. 理解从 MVP 到商业化的完整路径

### 第 1 课：什么是 RAG？为什么比纯 LLM 强

**核心知识点：**

1. **LLM 的知识截止问题**：大模型无法回答领域专有问题（如 2026 年最新录取分数线），幻觉率在专业场景高达 30%+
2. **RAG 的核心思想**：检索（Retrieval）+ 增强生成（Augmented Generation），让 LLM 先查资料再回答
3. **RAG vs Fine-tuning vs Prompt Engineering 的选型矩阵**：成本、效果、维护难度三维对比
4. **gaobao-advisor 架构全景**：一张图看懂整个系统——从用户输入到 RAG 检索到 LLM 生成到质量检查的完整流程
5. **RAG 的典型应用场景**：法律顾问、医疗问答、企业知识库、教育辅导、客服系统

**实操练习：**

> 用 OpenAI API 写一个最简单的 RAG demo：把一段文本切块、存入本地列表、用余弦相似度检索最相关的块、拼进 prompt 让 LLM 回答。要求：100 行以内，纯 Python，不依赖任何向量数据库。

**时长估计：** 45 分钟（理论 20 分钟 + 实操 25 分钟）

---

### 第 2 课：知识库设计——如何组织结构化知识

**核心知识点：**

1. **知识分块策略**：按标题拆分 vs 按段落拆分 vs 按语义拆分——gaobao-advisor 采用的是按 Markdown `##` 标题拆分，每个块 200-500 字
2. **知识分组（Group）设计**：将知识按主题域分成 6 个语义组（核心方法论、专业学校、职业前景、大学生活、数据格式、速查参考），每组配 10-15 个触发关键词
3. **嵌入向量 vs 关键词的双轨索引**：为什么不能只靠向量？关键词触发在精确查询（如省份名、专业名）上远优于语义相似度
4. **专家语录系统**：如何设计"金句库"——105 条结构化语录，按专业反向索引，在回答末尾自动注入增加说服力
5. **知识库的版本管理**：用 Markdown 管理知识、用 Git 追踪变更、用 CHANGELOG 记录每次更新

**实操练习：**

> 为你的目标领域设计知识库：(1) 确定 3-5 个知识组主题；(2) 每组写 2-3 个 Markdown 知识块；(3) 每组列出 5 个触发关键词；(4) 准备 3 条"金句"。输出格式要求：Markdown 文件，按 gaobao-advisor 的 `knowledge/groups/` 目录结构组织。

**时长估计：** 50 分钟（理论 25 分钟 + 实操 25 分钟）

---

### 第 3 课：向量数据库选型与部署

**核心知识点：**

1. **向量数据库全景**：Chroma（轻量本地）、FAISS（Facebook 高性能）、Pinecone（云端托管）、Weaviate（全功能）、Qdrant（Rust 实现）——各自适用场景与成本
2. **gaobao-advisor 的"零依赖"方案**：用 numpy 数组在内存中做向量检索，启动时加载，适合中小规模（<10 万文档块）场景，完全不依赖外部数据库
3. **嵌入模型选择**：OpenAI text-embedding-3-small（1536 维，云端）vs 通义千问 text-embedding-v3（云端）vs BGE-M3（本地 Ollama，零成本）——选型决策树
4. **嵌入预计算与缓存**：用 `.npy` 文件缓存嵌入向量，避免每次启动重新计算；增量更新策略
5. **从小到大的迁移路径**：numpy 内存方案 → Chroma 本地文件 → Qdrant/FAISS 生产部署，什么规模触发迁移

**实操练习：**

> (1) 在本地用 Ollama 部署 BGE-M3 嵌入模型；(2) 将第 2 课写的知识库文件做嵌入，存为 numpy 数组；(3) 实现一个简单的余弦相似度检索函数；(4) 对比 keyword-only、vector-only、hybrid 三种检索方式在 5 个测试查询上的效果。

**时长估计：** 60 分钟（理论 25 分钟 + 实操 35 分钟）

---

### 第 4 课：混合检索——向量 + 关键词的最佳实践

**核心知识点：**

1. **为什么纯向量检索不够**：向量相似度擅长语义匹配但不擅长精确匹配——搜"北京大学"可能返回"北大青鸟"
2. **gaobao-advisor 的混合检索公式**：`hybrid_score = 0.6 * vector_score + 0.4 * keyword_score`，为什么是 6:4 而不是 5:5？
3. **关键词评分机制**：触发词精确匹配 + 计数加权——每个知识组维护一个触发词列表，命中越多相关性越高
4. **语录的特殊评分**：专业名称精确匹配时 +0.3 加分，实现"提到计算机专业就精准推荐计算机相关语录"
5. **Top-K 与阈值过滤**：为什么选 Top 2 组而不是 Top 5？阈值 0.3 的意义——宁可少给知识也不要给错知识

**实操练习：**

> 将第 3 课的检索函数升级为混合检索：(1) 实现关键词评分（触发词匹配 + 计数）；(2) 实现向量评分（余弦相似度）；(3) 按 6:4 权重合并；(4) 用 10 个真实查询对比纯关键词、纯向量、混合检索的 Top-2 结果准确率。要求：在 notebook 或 Python 脚本中完成，输出每个查询的三种检索得分对比表。

**时长估计：** 55 分钟（理论 25 分钟 + 实操 30 分钟）

---

### 第 5 课：提示词工程——让 LLM 说人话

**核心知识点：**

1. **系统提示词的层次结构**：身份定义 → 认知模型 → 决策启发式 → 表达引擎 → 安全护栏——gaobao-advisor 652 行系统提示词的完整架构拆解
2. **表达引擎 v2.0**：8 种开场模板强制轮换（反问、直判、先夸后怼、叹气、拍桌、冷笑、自问、类比）、节奏公式（铺垫→反转→金句 ≤30 字）、禁用词清单（8 类含糊表达）
3. **三语调系统**：默认高强度（拍桌型）、务实温和（边界分数时）、共情优先（情绪危机时）——如何通过关键词检测自动切换
4. **9 项自检清单**：每条回复发送前必须通过 7/9 项检查（首句判断、金句存在、禁用词规避、口语化率 ≥70%、数据引用、无编造数据、长度合理、无 Markdown 残留等）
5. **提示词版本管理**：9 个历史版本归档（v2.0-v2.8）、14 个可复用模板、CHANGELOG 追踪每次迭代——如何系统化地迭代提示词

**实操练习：**

> (1) 为你的领域写一份 200 行以上的系统提示词，包含：身份定义、3 个认知模型、1 个表达引擎（至少 3 种开场模板 + 禁用词清单）、自检清单；(2) 用 3 个测试用例验证效果；(3) 写出第一个版本号和 CHANGELOG。参考 gaobao-advisor 的 `system_prompt.md` 和 `prompts/` 目录结构。

**时长估计：** 60 分钟（理论 30 分钟 + 实操 30 分钟）

### 第 6 课：多源数据管线——从 API 到数据库

**核心知识点：**

1. **三级数据源架构**：T1 本地数据库（置信度 90）→ T2 第三方 API（置信度 70）→ T3 搜索引擎（置信度 40）——为什么需要降级策略
2. **数据采集实战**：gaobao-advisor 的 3 个采集器（百度高考 API、百度搜索、掌上高考 API）如何实现 0.2 秒间隔的礼貌爬取、断点续传
3. **数据库设计**：10 张表的完整 schema 设计——学校表、专业表、录取分数表、招生计划表、学科排名表、会话表、反馈表等，以及 SQLAlchemy ORM 实现
4. **数据导入自动化**：脚本化批量导入（3003 所学校、7000+ 条录取分数）、定时更新（cron）、备份策略
5. **交叉验证**：多个数据源的结果如何交叉比对（分数容差 5 分、排名容差 10%），输出置信等级（高/中/低）

**实操练习：**

> (1) 设计你的目标领域的数据库 schema（至少 3 张核心表）；(2) 用 SQLAlchemy ORM 实现建表和基础 CRUD；(3) 写一个三级降级的数据查询函数：先查本地库，没有则调 API，再没有则搜搜索引擎；(4) 为每层结果标注置信度。提供 SQLite 起手，代码不超过 150 行。

**时长估计：** 60 分钟（理论 25 分钟 + 实操 35 分钟）

### 第 7 课：质量控制——AI 幻觉检测与防护

**核心知识点：**

1. **gaobao-advisor 的 7 层质量防线**：情绪检测 → 交叉验证 → 反模式检查 → AI 时代风险评估 → 决策框架 → 模型选择 → 知识注入——每一层的作用和实现原理
2. **情绪检测器**：关键词加权评分（危机词 +30、焦虑词 +15、紧张词 +5），三档响应策略（危机→共情优先→标准）
3. **反模式检查器**：8 条正则规则检测 AI 输出中的决策反模式——含糊判断、"跟着感觉走"、脱离家庭背景谈理想、学术黑话、无数据支撑的断言、过度含蓄、长篇铺垫、学术腔开头
4. **自我评估机制**：8 维度评分（0-100），低于 60 分的回复不上线——首句判断力、金句存在、禁用词、口语化率、数据引用、无编造、长度合理、无格式残留
5. **安全防护**：提示词注入检测（17 条正则模式）、SSRF 防御、XSS 消毒、输入截断、令牌桶限流（20 次/小时、40 次/天/IP）

**实操练习：**

> (1) 实现一个情绪检测器：输入用户消息，输出情绪等级（正常/紧张/焦虑/危机）；(2) 实现一个反模式检查器：输入 AI 回复，检测 3 种反模式（含糊判断、无数据断言、学术腔）；(3) 实现自我评估函数：给 AI 回复打 0-100 分。全部用正则 + 关键词实现，不依赖 LLM 判断。测试数据：各准备 5 条正例和反例。

**时长估计：** 60 分钟（理论 25 分钟 + 实操 35 分钟）

### 第 8 课：多端部署——CLI / Web / API / Docker

**核心知识点：**

1. **CLI 部署**：交互式终端聊天——`python agent.py` 启动、支持 `/slots`、`/reset`、`/stats` 等命令、Windows .bat 启动器
2. **Streamlit Web 部署**：`streamlit run app.py`——一步生成完整 Web UI、移动端适配、onboarding 引导流程、Streamlit Cloud 免费托管
3. **FastAPI REST API**：4 个核心端点（chat 同步、chat/stream SSE 流式、health 健康检查、reset 重置会话）、Swagger 自动生成文档
4. **Docker 部署**：Dockerfile 编写（Python 3.11-slim）、docker-compose 编排（Nginx 反向代理 + WebSocket 支持）、生产配置（资源限制 1 CPU / 1GB RAM）
5. **H5 移动端**：独立 HTML 聊天页，可嵌入微信 H5 和小程序 WebView

**实操练习：**

> 将你前几课构建的 AI 顾问部署到至少 2 种端口：(1) CLI 模式：写一个简单的终端聊天循环；(2) Web 模式：用 Streamlit 快速生成一个聊天界面；(3) （选做）Docker 模式：写 Dockerfile 并用 docker-compose 启动。要求：3 个部署目标共用同一个核心 Agent 类。

**时长估计：** 55 分钟（理论 20 分钟 + 实操 35 分钟）

### 第 9 课：运营与迭代——用户反馈驱动优化

**核心知识点：**

1. **数据埋点与分析**：事件追踪系统设计——会话数、情绪分布、槽位填充率、热门查询词、用户反馈率
2. **管理后台**：密码保护的运营面板——session 数量统计、情绪分布图、槽位完成率、热门省份/专业排行
3. **用户反馈闭环**：每条回复的"有用/没用"评分 → 定期分析低分回复 → 定位问题（检索不准？提示词不佳？数据缺失？）→ 针对性优化
4. **A/B 测试框架**：提示词版本对比、检索权重调整、新知识模块上线灰度
5. **内容运营**：55 条抖音脚本（gaobao-advisor 实际产出）→ 短视频引流 → 公众号沉淀 → 付费转化

**实操练习：**

> (1) 为你的 AI 顾问设计一个最小埋点方案（记录哪些事件、存在哪里）；(2) 实现一个简单分析函数：输入日志，输出"今日会话数 / 平均对话轮次 / 情绪分布 / Top 5 热门查询"；(3) 写一个运营周报模板：哪些回答质量差、哪些知识缺失、下周优化优先级。数据存储用 SQLite 即可。

**时长估计：** 45 分钟（理论 20 分钟 + 实操 25 分钟）

### 第 10 课：从 MVP 到产品——商业化路径

**核心知识点：**

1. **MVP 验证清单**：核心功能跑通、至少 10 个真实用户测试、NPS ≥ 7、能回答 80% 的常见问题
2. **收费模式设计**：免费试用（每日限次）→ 付费订阅（月/年）→ 企业定制（API 接入）——gaobao-advisor 的限流设计（20 次/小时/40 次/天）如何天然形成付费墙
3. **成本核算**：LLM API 调用成本（DeepSeek V3 vs Qwen-Plus vs GPT-4o）、服务器成本、数据更新成本——如何在 ¥0.01/次以下提供服务
4. **多平台分发**：独立部署 + 接入 Coze/Dify 等平台 + 微信小程序 + API 开放给第三方
5. **法律合规**：免责声明设计（gaobao-advisor 每条回复末尾自动追加）、数据隐私、AI 生成内容的法律风险

**实操练习：**

> (1) 写一份 1 页的商业画布：你的 AI 顾问是谁用的？解决什么问题？怎么收费？成本多少？(2) 设计你的限流策略：免费用户每天多少次？付费用户多少？(3) 写一条合规免责声明。课程结束时，你将拥有一个完整的商业化 checklist。

**时长估计：** 45 分钟（理论 25 分钟 + 实操 20 分钟）

## 课程二：AI Agent 开发入门（¥49，5 节课）

### 课程概述

本课程面向零经验但有 Python 基础的学习者，用 gaobao-advisor 中的 Agent 模块为案例，教你理解 AI Agent 与普通聊天机器人的本质区别，并从零实现一个能主动提问、调用工具、管理多轮对话的智能 Agent。5 节课，每节 30-40 分钟，聚焦核心概念与最小可运行 demo，不追求生产级质量，追求"跑通 + 理解 + 能改"。

### 目标学员

- 听过 AI Agent 但不清楚它和 ChatGPT 有什么区别的产品人/运营人

### 第 1 课：Agent 是什么？和 ChatBot 有什么区别

**核心知识点：**

1. **ChatBot 的局限**：无状态、无记忆、无主动权——用户问一句答一句，每次对话都是第一次见面
2. **Agent 的三个核心能力**：主动提问（槽位采集）、使用工具（API 调用、数据库查询）、记住上下文（多轮对话）
3. **gaobao-advisor 的 7 槽位系统**：省份、分数、选科、兴趣、地域、家庭情况、目标——理解 Agent 如何通过结构化信息收集来精准服务
4. **对话阶段管理**：探索期 → 定向期 → 精准推荐 → 风险审查——Agent 不只是回答问题，而是引导整个对话流程
5. **实际效果对比**：同一个问题，ChatBot 回答 vs Agent 回答的差异——Agent 能基于你提供的省份和分数给出定制化建议

**实操练习：**

> (1) 用 OpenAI API 写一个普通 ChatBot（纯问答，无状态）；(2) 加上最简单的"记忆"：把历史消息列表传入 API；(3) 对比两种模式在 3 轮对话中的表现差异。要求：30 行以内完成，纯 Python + OpenAI API。

**时长估计：** 30 分钟（理论 15 分钟 + 实操 15 分钟）

### 第 2 课：槽位采集——让 Agent 主动问对问题

**核心知识点：**

1. **什么是槽位（Slot）**：Agent 需要收集的关键信息字段——gaobao-advisor 定义了 7 个槽位，每个领域需要自己设计
2. **正则提取器**：用正则表达式从用户自然语言中提取结构化信息——"我是山东的，考了 580" → `{province: "山东", score: 580}`
3. **口语化处理**：中文口语解析——"五百八"→580、"刚过一本线"→一分一段表查询、方言别名（"阿拉"→上海）
4. **主动提问策略**：Agent 发现缺少关键信息时，如何自然地引导用户补充——不是机械地填表，而是像真人顾问一样在对话中"顺便"问
5. **槽位填充率**：7 个槽位的填充难度排序，哪些是核心槽位（省份、分数）必须优先获取

**实操练习：**

> (1) 为你的目标领域定义 3-5 个槽位（名称、类型、必填/可选）；(2) 写一个正则提取器，能从中文自然语言中提取这些槽位值；(3) 写一个槽位管理器：检查哪些槽位已填、哪些缺失、下一条消息应该问什么。提供测试用例：5 条用户消息，验证提取准确率。

**时长估计：** 35 分钟（理论 15 分钟 + 实操 20 分钟）

### 第 3 课：工具调用——让 Agent 查数据、做计算

**核心知识点：**

1. **工具调用的概念**：Agent 不仅能说话，还能"动手"——查询数据库、调用 API、执行计算
2. **gaobao-advisor 的数据查询管线**：9 种查询类型——录取分数查询、学校信息查询、就业数据查询、AI 时代风险评估、学校对比、历史趋势、专业百科、反向查询、匹配推荐
3. **工具定义模式**：给 LLM 描述"你有哪些工具可以用"——函数名、参数、返回值、使用场景
4. **三级降级策略**：工具查询失败时的优雅降级——本地数据库 → 第三方 API → 搜索引擎
5. **工具结果注入 Prompt**：查询结果如何格式化后注入到对话上下文中，让 LLM 基于真实数据回答

**实操练习：**

> (1) 实现 2 个简单工具函数（例如：查询某学校信息、计算两个选项的对比得分）；(2) 用 OpenAI function calling 或简单的关键词匹配让 Agent 决定何时调用工具；(3) 将工具返回结果注入对话，验证 Agent 能基于工具结果给出更准确的回答。总共不超过 80 行代码。

**时长估计：** 35 分钟（理论 15 分钟 + 实操 20 分钟）

### 第 4 课：多轮对话——状态管理与上下文记忆

**核心知识点：**

1. **对话状态机**：Agent 在不同阶段有不同的行为——gaobao-advisor 的 4 阶段（探索→定向→精准→风险审查），状态由槽位填充度和对话轮次共同决定
2. **上下文窗口管理**：LLM 有 token 限制，不能无限追加消息——gaobao-advisor 的策略：40 条消息时做上下文压缩（提取关键数据为摘要，保留最近 20 条），最大 100 条
3. **会话持久化**：用数据库保存对话记录，用户关闭页面后回来还能继续——gaobao-advisor 用 SQLAlchemy 存储 session_id + 消息列表
4. **快速通道**：当用户一开始就提供了足够信息（如"我是山东理科 580 分，想学计算机"），Agent 跳过探索阶段直接进入精准推荐
5. **流式输出**：SSE（Server-Sent Events）让回复实时逐字显示，而不是等完整回复再返回——用户体验的关键差异

**实操练习：**

> (1) 实现一个状态机：3 个状态（gathering → recommending → reviewing），定义状态转移条件；(2) 实现上下文压缩：消息超过 20 条时，将前面的消息压缩为一段摘要；(3) 用 Streamlit 实现一个简单的流式聊天界面。总代码量 100 行左右。

**时长估计：** 40 分钟（理论 15 分钟 + 实操 25 分钟）

### 第 5 课：部署上线——从本地到公网

**核心知识点：**

1. **本地运行到 Web 的三步走**：命令行 → Streamlit 一键 Web 化 → FastAPI 提供 API
2. **Streamlit 快速部署**：`streamlit run app.py` + Streamlit Cloud 免费托管（适合 demo 和 MVP）
3. **FastAPI 部署**：写 4 个端点（chat、stream、health、reset）、加 CORS、加限流、Swagger 文档自动生成
4. **基础安全**：输入长度限制、API Key 环境变量管理、限流（防止滥用和成本失控）
5. **上线 checklist**：环境变量检查、错误处理、日志记录、免责声明、用户隐私

**实操练习：**

> (1) 将前 4 课的 Agent 用 Streamlit 包装为 Web 应用；(2) （选做）用 FastAPI 暴露为 REST API；(3) 写一份上线清单（至少 8 项检查项）。目标：课程结束时，你有一个可以在浏览器中打开、给朋友演示的 AI Agent。

**时长估计：** 35 分钟（理论 10 分钟 + 实操 25 分钟）
