# 用户视角体验审计报告

> 审计日期：2026-06-12
> 审计视角：家长和学生（高考志愿填报场景）
> 审计范围：完整代码 + 架构 + 数据库 + UI 流程

---

## 一、🔴 高优先级 — 直接影响使用意愿

### 1. 必须自己配 API Key — 第一道拦路虎

**用户感受**：「我就是想查个志愿，为什么让我去搞什么 API Key？」

当前部署模式下，如果服务端没配置环境变量，用户必须在侧边栏输入自己的 `LLM_API_KEY`。错误提示还指向 DeepSeek 的链接（`app.py:369`）。这对家长和学生来说：

- 不知道什么是 API Key
- 不知道去哪里注册
- 不知道填完后能不能用、要花多少钱
- **直接劝退 90% 的非技术用户**

即使是「免配置」版本，`agnes-2.0-flash` 模型的能力上限也是隐性瓶颈。

---

### 2. 数据覆盖严重不足 — 核心功能打折

数据库只覆盖了**30 个省份中少数省份的 2-3 年数据**，且主要集中在 985/211 院校。这意味着：

- **普通本科和专科数据几乎没有**：全国 3000+ 院校中，种子数据只有 ~120 所顶级院校，导入脚本覆盖 ~80 所学校的分数线。占考生 80% 以上的"非重点"考生找不到自己的学校
- **年份断层**：只有近 2-3 年数据，无法看出趋势变化（如某校分数线连年上涨）
- **省份不均**：部分省份可能只有几条甚至零条录取分数记录
- **专业级分数线缺失**：大部分只有校级投档线，没有具体专业的分数线，而这恰恰是填志愿最需要的

**用户感受**：「我考了 480 分，想看看能上哪些二本学校，结果什么都查不到」

---

### 3. Streamlit 框架的天然缺陷

作为用户直接感知的 UI 层面：

- **每次交互都全页刷新**：Streamlit 的 `st.rerun()` 机制导致每次发消息后页面整体重绘，聊天记录会"闪一下"，体验远不如原生聊天应用流畅
- **无法在聊天中嵌入可交互元素**：不能点击学校名跳转详情、不能折叠/展开推荐列表、不能点赞/收藏学校——所有交互只能靠纯文本
- **移动端体验差**：虽然做了简单的 768px 响应式，但 Streamlit 在手机浏览器（尤其微信内置浏览器）中表现不稳定，侧边栏交互困难
- **加载速度慢**：Streamlit 每次交互都要重建整个页面状态，加上 LLM 推理时间，用户可能等 5-15 秒才看到回复
- **无法保持长连接**：关闭浏览器标签页后对话丢失，没有任何持久化

**用户感受**：「聊了半小时，手机切出去回个微信，回来全没了」

---

### 4. 对话上下文窗口限制 — 聊多了就"失忆"

系统只保留最近 20 条消息（10 轮对话）作为 LLM 上下文（`agent.py:415`）。但填志愿通常需要长时间反复讨论：

- 用户先聊了 10 轮确定方向，然后问「你之前推荐的那个武汉的学校叫什么来着？」→ AI 已经忘了
- 7 个 slot 虽然持久化在 session_state，但对话中的推理过程、反复权衡的细节全部丢失
- 没有任何"记忆增强"机制（如重要信息摘要）

---

## 二、🟡 中优先级 — 影响信任感和实用性

### 5. 数据可信度不透明

- AI 回复中偶尔会"自造数据"：因为 LLM 的幻觉问题，即使 system_prompt 要求"不编造数据"，仍可能产出看起来专业但实际不准的分数线
- 数据来源标注（T1/T2/T3/T4）对普通用户没有意义，用户不知道什么是"百度高考 API"、什么是"T4 网页抓取"
- 没有明确的**数据时效性声明**：用户不知道这些分数是 2024 还是 2023 的
- 没有"数据仅供参考，以官方公布的招生计划为准"这样的法律免责声明

**用户感受**：「这学校去年在我们省明明 610 才能上，怎么它说 595 就稳了？」

---

### 6. 快速提问按钮覆盖不全

6 个快速问题全是特定场景（湖北 580、河南文科 510、河北 600、专科 380、金融、选科）。全国 30+ 省份、文理/新高考多种模式、不同分数段的用户看到这些问题会觉得「跟我没关系」。

缺少：
- 按省份/分数段的分类入口
- 「我不知道自己该问什么」的引导流程
- 可以选择省份→输入分数→自动推荐的结构化表单

---

### 7. 缺少可视化结果展示

AI 推荐的学校全是**纯文本罗列**，没有：
- 冲/稳/保的分层卡片展示
- 学校关键信息的结构化面板（985 标签、城市、往年分数线趋势）
- 地图视图（哪些城市有推荐学校）
- 对比功能（两所学校放在一起比）
- 分数线走势折线图

**用户感受**：「推荐了 15 所学校，全是文字堆在一起，根本看不清重点」

---

### 8. "雪峰风格"可能冒犯部分用户

System prompt 中定义了 8 种对话"模板"（拍桌子、冷笑、反问等），30+ 禁用词（不许说"建议"、"或许"、"取决于"）。这种风格：

- 对追求实用的考生可能很爽
- **但对焦虑的家长可能显得不尊重**：「花了钱来咨询，你还在跟我摆谱？」
- 部分学生可能觉得被"教训"而抵触
- 虽然有情绪危机 SOP，但日常对话中的"毒舌"边界很难把控

---

### 9. 选科适配不够精准

虽然 system_prompt 中有"省份自适应 Step 0"来判断 3+3 / 3+1+2 / 传统文理模式，但：
- 新高考省份的"选科组合限制"没有显式查询：不是所有学校的所有专业都接受所有选科组合
- 用户说"我选了物化生"，系统不会主动检查目标专业是否要求某科
- `EnrollmentPlan` 表中有 `subject_requirement` 字段，但代码中没有查询它的逻辑

---

## 三、🟢 低优先级 — 体验优化空间

### 10. 没有收藏/对比/回看功能

用户反复问不同学校时，没有办法：
- 收藏感兴趣的学校
- 将几所学校放在一起对比
- 导出推荐结果（PDF / 截图 / 分享链接）
- 回看之前的对话历史（页面关闭就没了）

---

### 11. 没有"多人场景"

很多家庭是**爸妈+孩子一起看**，或者**跟亲戚朋友分享**。当前：
- 没有分享功能
- 没有多设备同步
- 没有微信小程序版本（虽然提到了微信兼容，但 Streamlit 在微信里体验很差）

---

### 12. 志愿表填报功能缺失

从"推荐学校"到"填报志愿表"之间有巨大鸿沟：
- 没有批次规则说明（提前批、本科一批、平行志愿规则）
- 没有志愿表模板生成（帮我排 96 个志愿的顺序）
- 没有调剂风险评估
- 没有"这个志愿表有没有问题"的审核功能

**用户感受**：「你推荐了学校，但我到底怎么填那个志愿表？哪个填第一个？」

---

### 13. 政策解读功能薄弱

- 数据库中 `search_policy()` 是硬编码的 5 种政策类型，且没有按省份筛选
- 没有最新的 2026 年各省招生政策变动
- 没有"强基计划"、"综合评价"、"专项计划"等特殊招生通道的个性化推荐
- 没有公费师范生、定向医学生等特殊类型的引导

---

### 14. 缺少"渐进式引导"设计

当前的交互模式是"你来问我来答"，缺少：
- 首次使用的分步引导（先选省份→再填分数→再说兴趣）
- 信息填写进度条（不只是侧边栏的小圆点，而是聊天流中的引导卡片）
- 「你还没告诉我你的分数哦」这样的主动提示（当前依赖 LLM 自觉提问）

---

## 四、信任模型总结

```
家长/学生对 AI 志愿顾问的信任 = 数据准确性 × 交互体验 × 结果可操作性

当前短板：
├── 数据准确性：★★☆☆☆  (覆盖不全，时效不明，无法验证)
├── 交互体验：  ★★☆☆☆  (Streamlit 刷新、无持久化、移动端差)
└── 结果可操作性：★★★☆☆  (纯文本推荐，缺可视化和志愿表工具)
```

---

## 五、最优先改进方向（投入产出比最高）

| 优先级 | 改进项 | 预期效果 |
|--------|--------|----------|
| P0 | 去掉 API Key 门槛 | 用户零感知，降低流失 |
| P0 | 扩大数据覆盖 | 覆盖二本及以上所有院校近 3 年分数线 |
| P1 | 增加结构化结果展示 | 冲/稳/保分层卡片 + 关键指标面板 |
| P1 | 加"志愿表生成"功能 | 从推荐到可填报的闭环 |
| P2 | 对话持久化 | 关闭页面不丢失 |
| P2 | 渐进式引导 | 新用户不再迷茫 |
