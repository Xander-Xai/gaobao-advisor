## OPC 赋能总览：免费工具如何养活一人公司

```
gaobao 免费开源（信任引擎）
    │
    ├── 用户使用 → 脱敏对话 → 内容素材（内容引擎）
    │       │
    │       ├── 抖音：15s Agent 录屏（劝退/逆袭/对比）
    │       ├── B站：5min 技术解析（"我如何用 AI 做高考顾问"）
    │       ├── 小红书：图文（选科避坑/专业劝退）
    │       └── 知乎：长文（志愿填报方法论 + 技术实现）
    │
    ├── GitHub 开源 → 技术品牌（品牌引擎）
    │       │
    │       ├── Star/Fork/Issue → 技术社区认可
    │       ├── 技术博客（RAG实战/Agent架构）→ SEO 长尾
    │       └── "我做了开源高考AI顾问" → B端信任背书
    │
    ├── 用户社群 → 私域沉淀（客户引擎）
    │       │
    │       ├── 微信群：家长/学生交流
    │       ├── 公众号：深度内容 + 服务入口
    │       └── 从 C端用户中发现 B端需求
    │
    └── 融入 OPC 业务矩阵（变现引擎）
            │
            ├── C端（20-30%）：知识付费课程 + 社群 + 模板
            └── B端（70-80%）：AI技术咨询 + Agent开发 + 行业解决方案
```

**核心公式：**

> **gaobao 免费用户 → 内容素材 → 平台流量 → 个人品牌 → C端知识付费 + B端技术咨询**

## Phase 5：上线冲刺（本周，6/13-6/15）

> 目标：修复阻塞项 → 部署上线 → 产品可用

### Task 5.1: 修复 2 个失败的 import pipeline 测试

**描述：** `test_import_scores_uses_province_curriculums` 和 `test_import_scores_checkpoint_saves_progress` 失败。原因是 `baidu_gaokao.py:302` 使用了 `.count()` 查询，但测试 mock 链只 mock 了 `.first()`，导致 `existing_count` 是 `MagicMock` 而非 `int`，`MagicMock > 0` 抛出 TypeError。

**修复方案：** 在两个测试函数中，mock chain 末尾添加 `.count.return_value = 0`。

**验收标准：**
- [ ] `python3 -m pytest tests/ -q` 全部 333 个测试通过
- [ ] 无新增 deprecation warning

**验证：**
- [ ] `python3 -m pytest tests/test_import_pipeline.py -v` 4/4 通过

**依赖：** 无

**涉及文件：**
- `tests/test_import_pipeline.py`（修改 2 个测试函数的 mock chain）

**预估规模：** XS（1 file，几行改动）

## Key Principles

1. **gaobao 永远免费开源** — 信任 > 短期收入
2. **内容是第一增长引擎** — 每个用户对话都是内容素材
3. **C 端养品牌，B 端养公司** — 知识付费验证 PMF，技术咨询才是利润核心
4. **gaobao = 案例作品** — 对 B 端客户来说，"我做了这个"比任何简历都有说服力
5. **数据是护城河** — 30 省数据 + 用户洞察，竞品追不上
6. **Agent 做 80%，人做 20%** — AI 降低边际成本，人提供信任溢价
