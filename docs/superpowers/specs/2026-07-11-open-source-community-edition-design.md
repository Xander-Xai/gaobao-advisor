# gaobao-advisor 社区开发者版开源设计

日期：2026-07-11
状态：待用户审阅

## 1. 目标

将 gaobao-advisor 整理为可安全公开、可由陌生开发者独立部署、可持续接受社区贡献的高考志愿 AI 顾问项目。

本次开源采用“社区开发者版”路线：

- MIT 开源应用核心代码、前后端、RAG/LLM 工作流和数据导入接口。
- 公开仓库只附合成数据或有明确再分发授权的少量样例数据。
- 真实高考数据、第三方内容和生产数据通过独立数据包、外部数据源或用户自行导入接入。
- 保留高考行业定位，但不暗示项目获得第三方人物、平台或教育机构官方授权。

## 2. 非目标

- 不在本轮公开生产数据库、数据库备份、用户对话或测试生成报告。
- 不保证所有第三方数据都可以随 MIT 代码一同分发。
- 不在本轮建设完整商业 SaaS、支付、组织管理或服务等级协议。
- 不在未完成安全和权利审查前推送、发布或部署到第三方平台。
- 不以重写核心业务架构为开源前提；只处理直接影响公开、部署和维护的技术债。

## 3. 当前基线与主要风险

设计基于 2026-07-11 的工作区取证：

- 工作区存在大规模未提交修改，因此先形成稳定发布快照，再做公开清理。
- Git 当前跟踪损坏数据库、数据库备份和测试报告，存在体积、隐私与历史泄露风险。
- 已有 MIT LICENSE、README、CONTRIBUTING、Issue/PR 模板和基础 CI。
- 缺少安全政策、行为准则、维护边界、代码所有者和变更日志。
- CI 尚未验证前端单测、前端生产构建、容器启动和完整历史秘密扫描。
- 默认配置同时启用本地 Ollama 和需要远程密钥的 embedding 服务，首次运行不能视为真正零配置。
- 数据、人物语录、品牌素材与代码许可证之间尚未形成明确的权利边界。

## 4. 开源架构边界

### 4.1 代码层

MIT 许可证覆盖项目方有权许可的源代码。依赖继续遵循各自许可证，并通过第三方声明和自动化扫描维护清单。

### 4.2 数据层

数据分为四类：

1. `sample`：合成或明确可再分发的演示数据，随仓库发布。
2. `user-imported`：用户自行导入的数据，不进入仓库。
3. `external`：运行时从第三方接口取得的数据，只保留适配器和来源说明。
4. `restricted`：权利不清晰、含个人信息或仅供内部使用的数据，不进入公开版本。

公开应用不得依赖 `restricted` 数据才能启动。数据文件使用独立的数据许可和来源清单，不默认继承 MIT。

### 4.3 内容与品牌层

- 项目品牌使用 gaobao-advisor / 高考志愿 AI 顾问。
- 第三方人物姓名、语录、文章摘录、Logo、字体和图片逐项记录来源及使用依据。
- 无法证明可再分发的内容从公开包移除或替换为摘要、链接、合成示例。
- README 和产品界面明确声明与第三方人物、平台、高校和教育机构不存在官方授权关系，除非有书面证据。

### 4.4 运行时数据层

用户对话、画像、报告、日志、会话密钥和监控数据只写入被忽略的运行目录。默认示例不得包含真实个人信息。

## 5. 发布流程设计

### Phase 0：发布冻结与证据清单

先确认当前用户改动的稳定边界，形成候选发布快照。所有清理均从该快照开始，避免把尚未验收的开发中状态当作开源基线。

交付物：

- 开源任务清单及逐项验收状态。
- 候选发布提交或独立公开镜像策略。
- 当前文件、Git 历史、依赖、数据和内容资产清单。

### Phase 1：仓库卫生与历史安全

从公开版本移除数据库、备份、报告、日志、会话文件、测试结果和构建产物；完善忽略规则。对工作树和完整 Git 历史运行秘密扫描。

如果历史含真实密钥、用户数据或不可公开的大文件，优先建立保留私有历史的干净公开镜像；只有在明确确认后才重写原仓库历史。发现过的真实密钥必须轮换，删除文件本身不能替代轮换。

验收：

- 公开候选中不存在生产数据库、备份、报告和用户内容。
- 完整历史秘密扫描不存在未处理的高置信度发现。
- 公开仓库没有异常大文件，运行产物均被自动忽略。

### Phase 2：许可、数据权利与隐私

新增代码许可说明、数据许可、数据来源、第三方声明、隐私说明和品牌声明。对每项可分发资产记录所有者、来源、许可、可修改性和再分发结论。

验收：

- 所有随仓库发布的数据和内容均有明确的再分发结论。
- 未确认权利的资产不进入公开候选。
- 演示数据不含真实姓名、联系方式、Token、IP、原始对话或可识别个人的信息。

### Phase 3：零配置演示路径

提供默认安全、可降级的开发者体验：

- 默认使用本地模型或 mock provider。
- 仓库附带最小合成数据集。
- 没有 embedding API Key 时关闭远程 embedding 或使用本地/简单检索回退。
- 语音、联网搜索和生产监控默认关闭。
- `docker compose up --build` 自动完成初始化并暴露健康检查。

验收：

- 干净克隆后，仅复制 `.env.example` 即可启动演示模式。
- 无第三方 API Key 时至少可以打开前端、通过健康检查并完成一个受控示例流程。
- 缺少可选服务时返回明确可操作的提示，而不是内部堆栈错误。

### Phase 4：CI 与供应链门禁

PR 门禁覆盖：

- Ruff lint 与 format。
- Python 3.10/3.11 测试和覆盖率阈值。
- `npm ci`、Vitest、前端生产构建。
- Docker Compose 构建与启动 smoke test。
- Gitleaks 秘密扫描。
- Python、npm 依赖漏洞审计。
- 许可证兼容性检查。
- OpenAPI、文档链接和占位符一致性检查。

发布增强包括 Dependabot 或 Renovate、SBOM、容器漏洞扫描、版本标签和 GHCR 镜像，但远程启用与发布需单独确认。

### Phase 5：社区治理与文档

补齐并统一：

- README 与英文概要。
- CONTRIBUTING。
- CODE_OF_CONDUCT。
- SECURITY。
- SUPPORT。
- CODEOWNERS。
- CHANGELOG。
- Issue/PR 模板、标签建议和 good first issue 清单。
- 架构、配置、数据导入、部署、故障排查文档。

README 必须区分稳定功能、实验性功能和当前不可用功能，并消除组织名、版本和启动命令占位符。

### Phase 6：高考 AI 专项治理

- 所有具体推荐明确显示数据年份、来源和适用范围。
- 无法验证的数据必须降级置信度并提示到官方渠道复核。
- 产品声明其为辅助决策工具，不构成录取或政策保证。
- 固定评测覆盖省份、分数段、选科、缺失字段、过期数据和提示注入场景。
- 对未成年人和家庭信息采用最小收集、最短保留和默认脱敏原则。

## 6. 配置与错误处理原则

- 所有秘密只通过环境变量或外部秘密管理注入。
- 生产模式禁止使用空密钥、随机临时会话密钥和默认管理员密码。
- 可选服务不可用时应局部降级，不得拖垮核心健康检查。
- 配置错误在启动阶段给出字段名、原因和修复方法，但不打印秘密值。
- 外部数据源失败时保留来源和时间信息，禁止以模型猜测替代真实数据。

## 7. 测试策略

### 静态验证

- 秘密、个人信息和大文件扫描。
- 许可证、数据来源、占位符和失效链接扫描。
- 配置、OpenAPI 与文档一致性检查。

### 自动化测试

- 后端单元和集成测试。
- 前端单元测试与生产构建。
- 无密钥演示模式测试。
- Docker Compose 健康检查。
- 依赖漏洞与容器漏洞扫描。

### 人工验收

- 新贡献者从干净环境按 README 启动。
- 提交一个最小 PR，确认模板和门禁可用。
- 检查高考推荐的来源、年份、免责声明和错误降级。

## 8. 完成定义

只有同时满足以下条件，才可将“开源准备完成”标为通过：

1. 干净克隆无需任何私有文件即可运行演示路径。
2. 当前文件和完整公开历史没有未处理秘密、用户数据和受限资产。
3. 公开候选不跟踪生产数据库、备份、测试报告或运行日志。
4. 所有分发数据、内容和品牌素材都有明确权利结论。
5. 前后端测试、构建、依赖审计和容器 smoke test 全部通过。
6. README 中的命令、链接、版本和功能状态与当前实现一致。
7. 安全、隐私、贡献、支持和行为准则文档齐全。
8. 高考推荐具备来源、年份、风险提示和官方复核路径。
9. 公开发布或推送由用户在最终验收后明确授权。

## 9. 关键风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 数据或语录无再分发权 | 下架、投诉或法律风险 | 代码与数据分离，未确认资产不发布 |
| Git 历史残留秘密或用户内容 | 凭据和隐私泄露 | 全历史扫描、干净镜像、密钥轮换 |
| 当前大规模未提交改动相互覆盖 | 丢失用户工作或形成错误基线 | 先冻结候选快照，逐文件隔离改动 |
| 无密钥模式实际不可用 | 新用户快速流失 | 合成数据、mock/本地 provider、明确降级 |
| 依赖审计受本地环境影响 | 错误宣称安全 | 在干净 CI 环境复核并保存机器可读结果 |
| 项目被误认为官方志愿服务 | 用户决策与品牌风险 | 明确非官方声明、来源和辅助决策边界 |

## 10. 实施顺序

实施严格按 Phase 0 至 Phase 6 推进。历史重写、远程仓库创建、推送、公开发布、镜像发布和第三方配置变更均不自动执行，必须在本地验收通过后获得用户明确授权。
