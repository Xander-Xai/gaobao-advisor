## 2. 验收方案设计

### 2.1 验收架构

验收分为 **6 大模块**，按依赖关系排序执行：

```
模块1: 数据完整性验收 (修复→补采→扩采)
   ↓
模块2: 数据准确性验收 (校验→清洗→标准化)
   ↓
模块3: 数据时效性验收 (真实性→更新机制→API可用性)
   ↓
模块4: 数据关联性验收 (外键→引用完整性→知识库关联)
   ↓
模块5: 业务场景验收 (核心查询→等位分→推荐验证)
   ↓
模块6: 安全与运维验收 (备份→幂等性→敏感数据)
```

### 2.2 模块1: 数据完整性验收

#### 1.1 修复2025年9省数据缺失 [CRITICAL]

**问题**: 河南/四川/陕西/云南/内蒙古/山西/宁夏/西藏/青海 2025年数据量仅为2024年的4%-30%。

**根因分析**: 这些是传统文理分科省份，2025年可能需要不同的 curriculum 参数，或 API 返回格式变化。

**验收步骤**:
1. 对每个缺失省份，运行 `import_2025_missing_provinces.py` 的逻辑，不带 curriculum 参数请求 API
2. 对比2024年数据量，目标: 2025年数据量 ≥ 2024年的 80%
3. 如果 API 仍无法返回足够数据，尝试掌上高考 API (zhiyuan.py) 作为备选
4. 记录每个省份的采集结果和剩余缺口

**通过标准**: 9省2025年数据量均 ≥ 2024年的80%

#### 1.2 西藏数据专项补采 [CRITICAL]

**问题**: 西藏仅49条记录，其他省5,000-23,000条。

**验收步骤**:
1. 检查 `import_xizang_data.py` 已导入的数据范围
2. 尝试百度高考 API 获取西藏全量数据
3. 如果 API 不可用，手动录入/从教育考试院官网抓取
4. 特别关注: 西藏分普通生源/西藏班、A类/B类特殊分类

**通过标准**: 西藏数据 ≥ 2,000条，覆盖2022-2025四年

#### 1.3 一分一段表补全 [HIGH]

**问题**: 25个省-年份组合缺失。

**缺失明细**:
- 2025年缺失: 云南/内蒙古/四川/宁夏/山西/河南/陕西/青海/黑龙江/西藏
- 2022-2023年缺失: 安徽/广西/江西/甘肃/西藏/贵州/黑龙江/吉林(2022-2023)

**验收步骤**:
1. 对2025年缺失省，从 admission_scores.min_rank 反推生成
2. 对2022-2023年缺失省，尝试从公开数据源获取原始一分一段表
3. 验证反推数据的合理性（总分段人数应与当年考生数匹配）

**通过标准**: 0个省-年份组合缺失

#### 1.4 专业级分数线扩采 [HIGH]

**问题**: 仅5.5%的记录有 major_id。

**验收步骤**:
1. 运行 `import_major_scores.py` 对 985/211 院校做专业级分数线采集
2. 验证 major_id 在 majors 表中存在
3. 目标: 985/211院校专业级分数线覆盖率 ≥ 80%

**通过标准**: 专业级记录占比 ≥ 30%，985/211院校 ≥ 80%

#### 1.5 招生计划补全 [MEDIUM]

**问题**: 仅2024-2025两年，且2025年部分省数据偏少。

**验收步骤**:
1. 补采2022-2023年招生计划
2. 补全2025年数据量不足的省份
3. 验证招生计划中的专业与 majors 表匹配

**通过标准**: 4年数据，各省每年 ≥ 2024年的80%

#### 1.6 院校排名补全 [HIGH]

**问题**: 70%院校无排名。

**验收步骤**:
1. 从软科排名/校友会排名获取最新院校排名
2. 导入并更新 schools.ranking 字段
3. 985/211院校排名必须完整

**通过标准**: 985/211院校100%有排名，总体 ≥ 60%有排名

#### 1.7 学科排名扩采 [HIGH]

**问题**: 仅29条学科排名记录。

**验收步骤**:
1. 从教育部第五轮学科评估结果批量导入
2. 覆盖985/211院校的A+/A/A-/B+/B等级学科
3. 目标: ≥ 1,000条学科排名记录

**通过标准**: ≥ 1,000条，覆盖所有985/211院校

### 2.3 模块2: 数据准确性验收

#### 2.1 分数合理性校验

**校验规则**:
- 非海南省份: 60 ≤ min_score ≤ 750
- 海南: 60 ≤ min_score ≤ 900
- 艺术类/体育类: 允许低于60分
- 同一院校同一专业相邻年份波动 ≤ 50分

**验收步骤**:
1. 全表扫描，标记越界分数
2. 相邻年份异常波动检测
3. 生成异常报告

**通过标准**: 0条越界记录，异常波动记录 ≤ 0.1%

#### 2.2 位次一致性校验

**校验方法**: 用一分一段表验证 admission_scores.min_rank 是否合理。

**验收步骤**:
1. 对每条有 min_rank 的记录，查 yi_fen_yi_duan 表
2. 验证: 该省该年该科类该分数对应的位次范围是否包含 min_rank
3. 允许 ±5% 的偏差（因为录取最低分可能对应一段区间）

**通过标准**: 位次一致性 ≥ 95%

#### 2.3 院校-省份归属校验

**验收步骤**:
1. 补全6所缺省份的院校
2. 验证院校所在省与 schools.province 一致
3. 验证 admission_scores 中的省份数据对应的院校确实在该省招生

**通过标准**: 0所院校缺省份，0条归属矛盾

#### 2.4 批次名称标准化

**现状**: 50+种批次名称。

**标准化映射**:
```
本科提前批 ← 本科提前批A段/B段/C段/提前批A段/提前批B段/...
本科一批 ← 本科一批/本科批A段/普通类一段(部分省份)
本科二批 ← 本科二批/本科批B段/本科二批及预科/...
本科批 ← 本科批/平行录取一段/普通类一段(新高考省)
专科批 ← 专科批/专科提前批/专科批F段/...
```

**验收步骤**:
1. 建立标准批次映射表
2. 在 admission_scores 中增加 standardized_batch 字段
3. 验证映射覆盖率 100%

**通过标准**: 所有记录有标准化批次，映射无歧义

#### 2.5 科类名称标准化

**标准化规则**:
- "3+3综合" → 保留（北京/天津/上海/浙江/山东/海南）
- "物理类"/"历史类" → 保留（新高考3+1+2省份）
- "理科"/"文科" → 保留（传统分科省份）
- "综合" → 需确认是"3+3综合"还是其他
- "艺术类（物理）" → 标记为异常

**验收步骤**:
1. 清洗"综合"类别，确认归属
2. 验证科类与省份高考模式匹配

**通过标准**: 0条"综合"未分类记录

#### 2.6 重复数据检测

**验收步骤**:
1. 按 (school_id, province, year, subject_type, batch, major_id) 去重
2. 按 (school_id, province, year, subject_type, batch, min_score) 近似去重
3. 生成重复报告

**通过标准**: 0条完全重复记录

#### 2.7 跨年异常波动检测

**验收步骤**:
1. 对同一院校同一省同一科类，计算相邻年份分数变化
2. 标记变化 > 50分的记录
3. 人工审核标记记录（可能是批次合并等原因导致）

**通过标准**: 异常波动 ≤ 0.5%，且有合理解释

### 2.4 模块3: 数据时效性验收

#### 3.1 2025年数据真实性确认

**验收步骤**:
1. 确认百度高考 API 返回的2025年数据来源（是否为正式发布数据）
2. 如果是预测/模拟数据，在数据中增加 source_type 标记
3. 检查2025年数据与2024年的变化是否合理

**通过标准**: 明确标注2025年数据来源和可信度

#### 3.2 数据更新机制验证

**验收步骤**:
1. 运行 `auto_update.sh`，验证增量更新是否正常
2. 验证断点续传: 中断后重新运行是否能正确恢复
3. 验证不会产生重复数据
4. 检查 crontab 配置是否正确

**通过标准**: 增量更新无错误，断点续传正常，无重复

#### 3.3 API 可用性测试

**验收步骤**:
1. 测试百度高考 API 各端点的可用性
2. 测试掌上高考 API 备选端点
3. 记录限流规则和错误率
4. 评估 API 稳定性风险

**通过标准**: 主 API 可用率 ≥ 95%，备选 API 可用
