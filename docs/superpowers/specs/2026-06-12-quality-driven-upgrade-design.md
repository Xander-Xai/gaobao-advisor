# 雪峰 Agent 质量驱动升级设计

> 设计时间：2026-06-12 | 方案：质量驱动（方案C）| 三期递进交付

---

## 一、目标

将 xuefeng-advisor 从"能用"升级为"不可替代"。核心路径：**先定义"好答案长什么样"，再倒逼需要什么数据来支撑。**

竞品弱点（来自 GitHub 调研）：
- 数据不准确：多数项目无交叉验证
- 无情绪处理：遇到崩溃的考生只会硬推方案
- 无 AI 时代视角：推荐专业时不说 4 年后的就业风险
- 部署门槛高：需要用户自己配 API Key

---

## 二、总体架构

在现有对话链路中插入 3 个质量控制节点：

```
用户输入 → 情绪检测 → 槽位采集 → 数据查询 → 交叉验证 → AI校正 → 质量自检 → 输出
              │            │           │           │          │          │
              ▼            ▼           ▼           ▼          ▼          ▼
         情绪档位      5槽位状态    多源查询    ≥2源一致    红黄绿区   8项自检
         (🟢🟡🔴)    (已填/未填)  (DB+API+搜索) (验证通过?)  (替代风险) (≥6项通过?)
```

新增模块（不改现有代码结构）：

```
quality/
├── emotion_detector.py      # 情绪检测（纯关键词，零成本）
├── cross_validator.py       # 数据交叉验证器
├── quality_checker.py       # 输出质量自检
└── ai_era_risk.py           # AI时代专业风险评估
```

## 三、一期：质量驱动升级（核心差异化）

### 3.1 情绪智能升级（emotion_detector.py）

**设计**：关键词匹配 + 加权评分 → 三档策略注入

```
用户消息 → 关键词扫描 → 情绪评分(0-100) → 档位判定 → 策略注入系统提示
```

三档策略：

| 桽位 | 触发条件 | 行为 |
|------|---------|------|
| 🟢 正常 | 评分 < 30 | 标准模式，直接分析 |
| 🟡 焦虑 | 30 ≤ 评分 < 70 | 先共情1句，再分析 |
| 🔴 崩溃 | 评分 ≥ 70 | 接住情绪→锚定→心理热线→简短方案→温暖收尾 |

情绪关键词库（加权评分）：

| 权重 | 关键词示例 |
|------|-----------|
| +30（高） | 崩溃、完蛋了、没救了、想死、不想活、废了、绝望 |
| +15（中） | 焦虑、怕、担心、迷茫、不知道怎么办、考砸了、复读 |
| +5（低） | 紧张、纠结、犹豫、不太确定 |

**特点**：纯关键词方案，不调用额外 LLM，零成本零延迟。

### 3.2 数据交叉验证（cross_validator.py）

**设计**：同一数据点同时查 2+ 来源，比对一致性后注入。

验证流程：

```
查询(school, province, year)
  ├── 来源1: 本地数据库 → db_result
  ├── 来源2: 百度高考API → api_result
  └── 来源3: 百度搜索(降级) → search_result

比对规则:
  - 分数差 ≤ 5分 → 一致
  - 分数差 > 5分 → 不一致
  - 仅1个来源 → 低置信度

输出:
  - 高置信度(≥2源一致) → 直接引用
  - 中置信度(2源不一致) → 引用 + "数据有差异，建议核实"
  - 低置信度(仅1源) → "仅供参考，请查官方"
  - 无数据 → "暂无数据，建议查省考试院"
```

### 3.3 AI 时代专业校正（ai_era_risk.py）

**设计**：维护结构化专业 AI 风险评估数据，推荐专业时自动附加风险提示。

数据结构：

```json
{
  "专业名称": {
    "risk_zone": "🟡",
    "risk_score": 45,
    "ai_impact": "具体影响描述",
    "recommendation": "建议方向",
    "salary_trend": "趋势描述",
    "source": "数据来源"
  }
}
```

风险分区：

| 区域 | 风险分 | 典型专业 |
|------|--------|---------|
| 🔴 红灯区 | ≥70 | 会计（基础）、行政管理、初级翻译、基础金融分析 |
| 🟡 黄灯区 | 30-69 | 计算机（基础方向）、法学（普通学校）、软件工程（初级） |
| 🟢 绿灯区 | <30 | 电气工程、临床医学、护理、集成电路、新能源 |

调用方式：推荐专业时自动查询该专业的 AI 风险等级，附加 1 句话提示。

### 4.1 分数线扩展：20省 → 31省

- 现有脚本 `import_baidu_gaokao.py --top-n 200` 扩展采集
- 预计新增 3000-5000 条录取数据
- 为交叉验证提供数据基础

### 4.2 语录扩充：105条 → 500+

| 来源 | 预计新增 | 处理方式 |
|------|---------|---------|
| SPA3K/Xue-Feng-Skill B站视频ASR | 200-300条 | 提取精华观点，结构化JSON |
| 张雪峰著作OCR文本 | 100-150条 | 提取经典判断和建议 |
| 网络公开讲座/直播 | 50-100条 | 人工筛选+结构化 |

结构化格式（兼容现有 _by_major.json）：

```json
{
  "id": "q_106",
  "text": "语录内容",
  "category": "zhuanye|jiuye|rensheng|yuanxiao|xuexi|zhiyuan-celue",
  "major_tags": ["专业标签"],
  "context": "场景描述",
  "source": "来源说明"
}
```

扩充后重新生成 `_by_major.json` 索引。

## 五、三期：部署优化

### 5.1 Streamlit Cloud（完整版）

- 在 Streamlit Cloud Settings → Secrets 配置 API Key
- 用户打开链接直接聊天，零配置
- 费用：DeepSeek 约 1 元/500 次咨询

### 5.2 扣子 Bot（免费轻量版）

- 在 coze.cn 创建 Bot，上传 system_prompt + knowledge_base
- 配置工作流：槽位采集 → 知识检索 → LLM 生成
- 发布为 Web 链接 + 二维码
- 完全免费（字节承担模型费用）
- 适合微信扫码分享、引流

### 5.3 双渠道互补

| 维度 | Streamlit Cloud | 扣子 Bot |
|------|----------------|---------|
| 完整度 | 完整（含数据库、验证） | 轻量（知识库+对话） |
| 成本 | LLM API 费用 | 完全免费 |
| 分享 | 网页链接 | 微信二维码 |
| 适合 | 深度使用 | 快速体验+引流 |
