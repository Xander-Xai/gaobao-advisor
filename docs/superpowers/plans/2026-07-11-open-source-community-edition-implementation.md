# gaobao-advisor 社区开发者版开源实施计划

设计依据：`docs/superpowers/specs/2026-07-11-open-source-community-edition-design.md`

## 概述

本计划把开源准备拆为可独立验证的小任务。实施顺序优先处理不可逆或高风险事项，但不会自动重写 Git 历史、推送远程、公开仓库、发布镜像或修改第三方资源。当前工作区已有大量用户改动，每个任务都只修改明确列出的文件，并在提交前检查暂存区，避免混入现有改动。

## 架构决策

- 采用“代码公开、数据分层”的社区开发者版结构。
- 公开仓库只包含合成或有明确许可的样例数据。
- 优先建立干净公开镜像，避免直接重写当前私有仓库历史。
- 默认演示路径不依赖付费或远程 API；生产能力通过显式配置启用。
- 安全、隐私、数据来源和高考决策边界属于发布门禁，不是可选文档。
- 所有自动化验收先在本地或 CI 配置中落地，远程启用需最终授权。

## 依赖关系

```text
发布基线
  -> 仓库卫生与扫描
      -> 权利/治理文档
      -> 演示配置与样例数据
          -> 前后端及容器 CI
              -> README 与发布文档
                  -> 最终公开候选验收
```

## Phase 0：发布基线

### Task 1：生成开源资产和风险清单

**描述：** 建立可重复生成的当前仓库清单，记录被跟踪的大文件、运行产物、数据库、备份、报告、可能的秘密文件、数据及内容资产。

**验收标准：**

- [ ] 清单区分代码、数据、内容、运行产物和受限资产。
- [ ] 每个高风险发现包含路径、风险和拟定处置。
- [ ] 清单由脚本生成或由明确命令复核，不依赖手工印象。

**验证：**

- [ ] 运行 `bash scripts/audit_open_source.sh` 返回明确状态。
- [ ] 对照 `git ls-files`，确认数据库、备份和报告没有漏报。

**依赖：** 无。

**预计涉及文件：**

- `scripts/audit_open_source.sh`
- `docs/open-source-readiness.md`

**规模：** 小。

### Task 2：固定公开候选策略

**描述：** 在开源就绪文档中明确当前私有历史保留、公开候选使用干净镜像的策略，并记录当前候选提交、未提交改动及远程发布边界。

**验收标准：**

- [ ] 文档明确不自动重写现有历史。
- [ ] 文档记录公开镜像的创建和复核步骤。
- [ ] 文档明确推送与公开需要用户最终授权。

**验证：**

- [ ] `rg -n "干净镜像|历史重写|最终授权" docs/open-source-readiness.md` 命中对应条款。

**依赖：** Task 1。

**预计涉及文件：**

- `docs/open-source-readiness.md`

**规模：** 小。

## Phase 1：仓库卫生与历史安全

### Task 3：隔离运行产物

**描述：** 完善 Git 和 Docker 忽略规则，覆盖报告、前端测试结果、数据库、备份、日志、会话文件、监控状态及本地工具产物。

**验收标准：**

- [ ] 新生成的报告和前端测试结果不会出现在 `git status`。
- [ ] Docker 构建上下文不包含数据库、备份、测试和本地秘密。
- [ ] 必须保留的样例数据通过显式例外规则纳入。

**验证：**

- [ ] 使用 `git check-ignore -v` 验证每类运行产物。
- [ ] 使用 `docker buildx du` 或归档清单复核构建上下文。

**依赖：** Task 1。

**预计涉及文件：**

- `.gitignore`
- `.dockerignore`

**规模：** 小。

### Task 4：从公开候选移除受限和大体积产物

**描述：** 将已跟踪数据库、备份和测试报告从公开候选的版本控制清单中移除，并保留必要的本地文件备份策略。此任务不重写历史。

**验收标准：**

- [ ] `git ls-files` 不再列出生产数据库、损坏数据库、数据库备份和测试报告。
- [ ] 应用不依赖这些文件完成演示启动。
- [ ] 清理操作不删除用户唯一的数据副本。

**验证：**

- [ ] `git ls-files | rg '(backups/|data/reports/|\.(db|sqlite))'` 只允许经批准的样例文件。
- [ ] 运行样例数据初始化测试。

**依赖：** Task 3。

**预计涉及文件：**

- `backups/`
- `data/reports/`
- `data/gaokao.db.corrupted`
- `docs/open-source-readiness.md`

**规模：** 中。

### Task 5：建立秘密与敏感信息扫描门禁

## 风险与缓解

| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 现有用户改动与开源改造重叠 | 误覆盖或提交无关内容 | 每个任务检查基线 diff，只暂存明确文件 |
| 删除受限文件时丢失唯一数据 | 数据不可恢复 | 先确认本地副本和公开候选策略，再取消跟踪 |
| 数据权利无法内部确认 | 无法证明可公开 | 默认不分发，只保留导入器和结构 |
| 本地环境不能运行安全工具 | 门禁证据不完整 | 使用隔离工具环境和 CI 双重验证 |
| Docker 或模型下载耗时过长 | 验收延迟 | 分离配置检查、构建和完整运行证据，不降低门禁 |
| 远程发布产生不可逆外部影响 | 意外公开 | 保留最终人工授权门禁 |

## 实施纪律

- 每完成 2-3 个任务更新一次就绪报告和任务状态。
- 修改前检查目标文件是否已有用户改动，重叠时先做逐块 diff。
- 文件编辑使用小范围补丁，不执行 `git reset --hard` 或覆盖式恢复。
- 不把历史报告中的测试数字当成当前证据。
- 每次提交只包含本轮明确文件，并在提交前检查 `git diff --cached`。
